# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные
В данном разделе описаны интерфейсы данных, которые были разработаны при разборе проекта, а также указано их прямое назначение в приложении.

#### Интерфейс товара (`IProduct`)
* **Назначение:** Описывает структуру данных отдельного товара (карточки), загружаемого с внешнего сервера и используемого для отображения на витрине, в модальном окне подробного описания или внутри списка корзины.
```typescript
interface IProduct {
  id: string;                 // Уникальный идентификатор товара
  description: string;        // Подробное текстовое описание товара для модального окна
  image: string;              // URL-ссылка на изображение товара
  title: string;              // Название (наименование) товара
  category: string;           // Категория товара (например, "софт-скилл", "кнопка")
  price: number | null;       // Цена товара (может быть null, если товар бесценный)
}
```

#### Интерфейс покупателя (`IBuyer`)
* **Назначение:** Описывает персональные, контактные и платежные данные покупателя, которые заполняются пользователем на шагах оформления заказа через формы приложения.
```typescript
interface IBuyer {
  payment: TPayment | null;   // Вид оплаты (изначально null, выбирается пользователем, например: 'card' | 'cash')
	email: string;              // Электронная почта покупателя
	phone: string;              // Номер телефона для связи
  address: string;            // Адрес доставки товара
}
```

#### Интерфейс полного заказа (`IOrder`)
* **Назначение:** Расширяет интерфейс данных покупателя (`IBuyer`), добавляя информацию о составе корзины и итоговой стоимости для последующей отправки на сервер.
```typescript
interface IOrder extends IBuyer {
  total: number;              // Итоговая сумма заказа
  items: string[];            // Массив уникальных ID покупаемых товаров
}
```

#### Интерфейс ответа сервера при заказе (`IOrderResult`)
* **Назначение:** Описывает структуру объекта, который приходит от сервера в ответ на успешное оформление покупки.
```typescript
interface IOrderResult {
  id: string;                 // Уникальный идентификатор созданного заказа
  total: number;              // Итоговая списанная сумма покупки
}
```

#### Интерфейс ответа сервера со списком товаров (`IApiProductsResponse`)
* **Назначение:** Описывает структуру объекта, возвращаемого сервером при GET-запросе каталога товаров.
```typescript
interface IApiProductsResponse {
  total: number;              // Общее количество доступных товаров на сервере
  items: IProduct[];          // Массив объектов самих товаров
}
```

### Модели данных
В данном разделе описаны все классы, которыми реализована работа с данными в приложении. Они отвечают за хранение информации и бизнес-логику работы с ней. При любом изменении своего внутреннего состояния модели реактивно генерируют события через брокер событий (паттерн Наблюдатель), уведомляя Презентер о необходимости перерисовки интерфейса.

#### Класс Каталог товаров (`CatalogModel`)
* **Назначение и зона ответственности:** Отвечает за хранение полного массива товаров, доступных для покупки в приложении, а также за хранение товара, выбранного пользователем для подробного отображения в модальном окне.
* **Конструктор класса:** `constructor(events: IEvents)` — принимает экземпляр брокера событий для уведомления системы об изменениях.
* **Поля класса:**
  * `private items: IProduct[]` — массив всех товаров, доступных в приложении.
  * `private preview: IProduct | null` — товар, выбранный для подробного отображения (или `null`).
  * `private events: IEvents` — брокер событий для отправки уведомлений.
* **Методы класса:**
  * `setItems(items: IProduct[]): void` — сохраняет массив товаров внутри модели и генерирует событие `items:changed`.
  * `getItems(): IProduct[]` — возвращает текущий сохраненный массив всех товаров из модели.
  * `getItemById(id: string): IProduct | undefined` — возвращает один конкретный товар по его id.
  * `setPreview(item: IProduct | null): void` — сохраняет выбранный товар для подробного отображения и генерирует событие `preview:changed`.
  * `getPreview(): IProduct | null` — возвращает товар, выбранный в данный момент для подробного отображения.

#### Класс Корзина (`BasketModel`)
* **Назначение и зона ответственности:** Отвечает за хранение массива товаров, которые пользователь выбрал для покупки, а также реализует методы для управления этим списком и подсчета итоговых метрик.
* **Конструктор класса:** `constructor(events: IEvents)` — принимает экземпляр брокера событий для уведомления системы об изменениях.
* **Поля класса:**
  * `private basketItems: IProduct[]` — массив товаров, выбранных покупателем для покупки.
  * `private events: IEvents` — брокер событий для отправки уведомлений.
* **Методы класса:**
  * `getBasketItems(): IProduct[]` — возвращает массив всех товаров, которые находятся в корзине в текущий момент.
  * `addBasketItem(item: IProduct): void` — добавляет товар в массив корзины и генерирует событие `basket:changed`.
  * `removeBasketItem(id: string): void` — удаляет товар из массива корзины по его id и генерирует событие `basket:changed`.
  * `clearBasket(): void` — производит полную очитку корзины и генерирует событие `basket:changed`.
  * `getTotalPrice(): number` — рассчитывает и возвращает суммарную числовую стоимость всех товаров в корзине.
  * `getBasketCount(): number` — возвращает текущее количество товаров в корзине.
  * `isInBasket(id: string): boolean` — выполняет проверку наличия товара в корзине по его id.

#### Класс Покупатель (`BuyerModel`)
* **Назначение и зона ответственности:** Отвечает за хранение данных покупателя, которые тот должен указать при оформлении заказа (вид оплаты, адрес, телефон, email). Вычисление ошибок валидации происходит динамически.
* **Конструктор класса:** `constructor(events: IEvents)` — принимает экземпляр брокера событий для уведомления системы об изменениях.
* **Поля класса:**
  * `private payment: TPayment | null` — приватное поле для хранения вида оплаты.
  * `private email: string` — приватное поле для хранения email покупателя.
  * `private phone: string` — приватное поле для хранения телефона покупателя.
  * `private address: string` — приватное поле для хранения адреса доставки.
  * `private events: IEvents` — брокер событий для отправки уведомлений.
* **Методы класса:**
  * `setBuyerField(field: keyof IBuyer, value: string): void` — сохраняет данные конкретного поля в модели и генерирует событие `buyer:changed`.
  * `getBuyerData(): IBuyer` — возвращает все накопленные данные покупателя в виде единого объекта.
  * `clearBuyerData(): void` — производит полную очистку данных покупателя, сбрасывая их в начальное состояние, и генерирует событие `buyer:changed`.
  * `validateBuyerData(): TBuyerErrors` — выполняет валидацию данных. Метод динамически формирует и возвращает объект типа `TBuyerErrors`. Для полей первого шага (способ оплаты и адрес) проверяется их наличие. Для полей второго шага (email и телефон) проверяется не только их заполненность, но и строгое соответствие форматам с помощью регулярных выражений (валидация корректности ввода `@` и доменной зоны для почты, а также маски количества цифр для номера телефона). Если ошибок нет, возвращается пустой объект `{}`.

### Слой коммуникации
В данном разделе описан класс, выступающий представителем коммуникационного слоя приложения «Web-Larek». Он отвечает за отправку запросов на сервер и получение ответов, изолируя сетевую логику от остального кода приложения.

#### Класс `ApiWebLarek`
* **Назначение и зона ответственности:** 
  Класс представляет собой представитель коммуникационного слоя приложения «Web-Larek». Использует паттерн «Композиция» для работы с сетью, не привязываясь напрямую к конкретной реализации сетевого класса. Отвечает за получение актуального каталога товаров с сервера, а также за отправку сформированного заказа покупателя.

* **Конструктор класса:**
  `constructor(api: IApi)` — принимает объект, соответствующий интерфейсу `IApi`, содержащий методы `get` и `post` для отправки и получения данных.

* **Поля класса:**
  * `private api: IApi` — приватное поле для хранения переданного сетевого объекта коммуникации.

* **Методы класса:**
  * `getProductList(): Promise<IApiProductsResponse>` — выполняет GET-запрос на эндпоинт `/product` через объект `api`. Возвращает промис с объектом `IApiProductsResponse`, полученным от сервера, внутри которого находится массив товаров `items` и их общее количество `total`.
  * `createOrder(order: IOrder): Promise<IOrderResult>` — принимает объект оформленного заказа `order` и отправляет его POST-запросом на эндпоинт `/order` через объект `api`. Возвращает промис с объектом `IOrderResult`, подтверждающим покупку на определенную сумму.

### Слой представления (View)
Все компоненты слоя представления наследуются от базового абстрактного класса `Component<T>` и отвечают за отображение интерфейса на странице, поиск элементов в DOM-дереве, установку текстовых и визуальных значений и первичную обработку действий пользователя. Взаимодействие со связующим слоем (Презентером) строится на генерации событий.

Поля классов представления хранят исключительно ссылки на HTML-элементы. Компоненты не хранят внутри себя состояние данных и не принимают самостоятельных решений об изменении разметки.

#### 1. Группа компонентов Карточки товара
Базовый класс объединяет общую логику отображения, а дочерние классы адаптируют её под конкретные шаблоны (темплейты) вёрстки.

* **Базовый класс Карточка (`Card`)**
  * **Назначение:** Описывает общие элементы карточки товара, используемые во всех шаблонах приложения, вынося в себя общий функционал для дочерних классов.
  * **Конструктор:** `constructor(container: HTMLElement, actions?: ICardActions)` — принимает контейнер разметки и опциональный объект с обработчиками действий. Находит элементы и вешает слушатели один раз.
  * **Поля класса:**
    * `protected titleElement: HTMLElement` — элемент названия товара.
    * `protected priceElement: HTMLElement` — элемент отображения цены.
    * `protected imageElement?: HTMLImageElement` — элемент картинки товара.
    * `protected categoryElement?: HTMLElement` — элемент текстовой категории.
    * `protected buttonElement?: HTMLButtonElement` — элемент кнопки действия.
  * **Методы (Сеттеры):**
    * `set title(value: string)` — устанавливает название товара.
    * `set price(value: number | null)` — выводит цену в формате `X синапсов` или строку `Бесценно`, если цена равна `null`.
    * `set image(value: string)` — устанавливает URL картинки через утилиту `setImage`.
    * `set category(value: string)` — устанавливает текст категории и динамически переключает CSS-модификатор фона (из объекта `categoryMap` файла `constants.ts`): `card__category_soft`, `card__category_hard`, `card__category_button`, `card__category_additional`, `card__category_other`.
    * `set image(value: string)` — устанавливает URL картинки через утилиту `setImage`. Слой представления самостоятельно проверяет пришедший путь и при необходимости склеивает относительный адрес от бэкенда с константой `CDN_URL` из файла `constants.ts`, инкапсулируя логику подготовки путей внутри себя.

* **Класс Карточка каталога (`CardCatalog`)**
  * **Назначение:** Отображает карточку на главной витрине сайта внутри сетки товаров.
  * **События:** При клике на контейнер карточки генерирует событие `card:select` для открытия подробного превью.

* **Класс Карточка просмотра (`CardPreview`)**
  * **Назначение:** Отображает подробную информацию о товаре в модальном окне.
  * **Поля класса:**
    * `protected descriptionElement: HTMLElement` — элемент длинного текстового описания товара.
  * **Методы (Сеттеры):**
    * `set description(value: string)` — устанавливает подробное описание.
    * `setButtonState(isInBasket: boolean, isPriceNull: boolean): void` — метод управления состоянием кнопки. Если цена `null`, блокирует кнопку (`disabled = true`) и пишет `Недоступно`. Если товар в корзине — меняет текст на `Удалить из корзины`, если нет — на `Купить`.
  * **События:** Клик по кнопке генерирует события добавления (`basket:add`) или удаления (`basket:remove`) товара.

* **Класс Карточка в корзине (`CardBasket`)**
  * **Назначение:** Отображает товар в виде компактной строки списка внутри модального окна корзины.
  * **Поля класса:**
    * `protected indexElement: HTMLElement` — элемент порядкового номера товара в списке.
  * **Методы (Сеттеры):**
    * `set index(value: number)` — устанавливает порядковый номер строки.
  * **События:** Клик по кнопке-мусорке генерирует событие удаления товара по его ID (`basket:remove`).

#### 2. Группа компонентов Форм
Базовый класс берёт на себя рутинную работу с HTML-формами (сбор данных, валидация), а дочерние классы описывают конкретные поля ввода.

* **Базовый класс Форма (`Form<T>`)**
  * **Назначение:** Выступает общим родителем для всех форм. Управляет валидацией, отображением ошибок и состоянием кнопки отправки.
  * **Конструктор:** `constructor(container: HTMLFormElement, events: IEvents)` — вешает общие слушатели событий `input` и `submit` один раз.
  * **Поля класса:**
    * `protected submitButton: HTMLButtonElement` — кнопка отправки формы.
    * `protected errorsContainer: HTMLElement` — контейнер для вывода текста ошибок валидации.
  * **Методы (Сеттеры):**
    * `set valid(value: boolean)` — включает или отключает доступность кнопки отправки (`disabled`).
    * `set errors(value: string[])` — принимает строго массив строк с ошибками валидации (`string[]`) и динамически выводит их в контейнер, самостоятельно объединяя элементы массива в единую строку через разделитель `". "`.
  * **События:** Генерирует динамические события изменения полей вида `[имя_формы].[имя_поля]:change` при вводе данных, и событие сабмита `[имя_формы]:submit`.

* **Класс Форма заказа (`FormOrder`)**
  * **Назначение:** Компонент первой формы оформления заказа (Шаг 1: способ оплаты и адрес доставки).
  * **Поля класса:**
    * `protected cardButton: HTMLButtonElement` — кнопка выбора оплаты онлайн.
    * `protected cashButton: HTMLButtonElement` — кнопка выбора оплаты при получении.
  * **Методы (Сеттеры):**
    * `set payment(value: string)` — переключает CSS-модификатор активной кнопки `button_alt-active` для выбранного способа оплаты.
    * `set address(value: string)` — устанавливает значение в инпут адреса.

* **Класс Форма контактов (`FormContacts`)**
  * **Назначение:** Компонент второй формы оформления заказа (Шаг 2: email и телефон).
  * **Методы (Сеттеры):**
    * `set email(value: string)` — устанавливает значение в инпут почты.
    * `set phone(value: string)` — устанавливает значение в инпут телефона.

#### 3. Универсальные компоненты страницы

* **Класс Модальное окно (`Modal`)**
  * **Назначение:** Универсальный изолированный контейнер («коробка») для отображения любого контента (превью, корзины, форм) во всплывающем окне. Не имеет дочерних классов.
  * **Конструктор:** `constructor(container: HTMLElement, events: IEvents)` — находит элементы и вешает слушатели закрытия один раз.
  * **Поля класса:**
    * `private closeButton: HTMLButtonElement` — кнопка-крестик для закрытия окна.
    * `private contentContainer: HTMLElement` — контейнер для динамического содержимого.
    * `private pageWrapper: HTMLElement` — элемент-обёртка всей страницы для блокировки прокрутки.
  * **Методы:**
    * `open(): void` — открывает окно добавлением модификатора `modal_active` и блокирует скролл страницы через класс `page__wrapper_locked`.
    * `close(): void` — закрывает окно, убирая модификаторы, и очищает контент.
    * `set content(value: HTMLElement)` — сеттер для динамической подмены вёрстки внутри модального окна.
  * **События:** Генерирует события `modal:open` и `modal:close` при изменении видимости. Закрывается по клику на крестик или оверлей.

* **Класс Главная страница (`Page`)**
  * **Назначение:** Управляет главными контейнерами сайта — сеткой товаров, счётчиком корзины в шапке и блокировкой прокрутки.
  * **Поля класса:**
    * `protected counterElement: HTMLElement` — элемент цифрового счётчика на иконке корзины.
    * `protected galleryElement: HTMLElement` — контейнер-сетка для вывода карточек товаров.
    * `protected wrapperElement: HTMLElement` — главный контентный контейнер страницы.
    * `protected basketButton: HTMLButtonElement` — кнопка-иконка корзины в шапке сайта.
  * **Методы (Сеттеры):**
    * `set counter(value: number)` — обновляет текстовое число на счётчике корзины.
    * `set catalog(cards: HTMLElement[])` — принимает массив готовых отрендеренных карточек и вставляет их в галерею методом `replaceChildren`.
  * **События:** Клик по кнопке корзины генерирует событие `basket:open`.

* **Класс Корзина (`Basket`)**
  * **Назначение:** Отображает список выбранных товаров, их общую стоимость и кнопку перехода к оформлению.
  * **Поля класса:**
    * `protected listElement: HTMLElement` — элемент-контейнер для вывода списка строк товаров.
    * `protected totalElement: HTMLElement` — элемент для вывода суммарной стоимости.
    * `protected orderButton: HTMLButtonElement` — кнопка «Оформить».
  * **Методы (Сеттеры):**
    * `set items(cards: HTMLElement[])` — принимает массив строк товаров. Если массив пуст, отключает кнопку «Оформить» (`disabled = true`) и выводит текст `Корзина пуста`.
    * `set total(value: number)` — устанавливает итоговую сумму в синапсах.
  * **События:** Клик по кнопке «Оформить» генерирует событие `order:open`.

* **Класс Окно успеха (`Success`)**
  * **Назначение:** Показывает финальное модальное окно об успешной оплате заказа бэкендом.
  * **Поля класса:**
    * `protected descriptionElement: HTMLElement` — элемент для вывода текста списанной суммы.
    * `protected buttonClose: HTMLButtonElement` — кнопка «За покупками!».
  * **Методы (Сеттеры):**
    * `set total(value: number)` — устанавливает текст вида `Списано X синапсов`.
  * **События:** Клик по кнопке «За покупками!» генерирует событие `order:clear`.

### Сводная таблица событий приложения
В приложении используется брокер событий (`EventEmitter`) для связи слоёв Представления (View) и Моделей данных (Model) через Презентер. Ниже описаны ключевые события, генерируемые в системе:

| Название события | Источник события | Описание события |
|------------------|------------------|------------------|
| `items:changed`  | `CatalogModel`   | Вызывается при успешной загрузке или обновлении товаров в модели каталога для перерисовки витрины |
| `preview:changed`| `CatalogModel`   | Сигнализирует о том, что выбран товар для подробного просмотра |
| `basket:changed` | `BasketModel`    | Генерируется при любом изменении состава корзины (добавлении/удалении). Обновляет счётчик в шапке и итоговую сумму |
| `buyer:changed`  | `BuyerModel`     | Сигнализирует об изменении персональных или платежных данных покупателя |
| `card:select`    | `CardCatalog`    | Вызывается при клике на карточку товара на главной витрине для открытия её превью |
| `basket:add`     | `CardPreview`    | Вызывается при клике на кнопку «Купить» в модальном окне превью товара |
| `basket:remove`  | `CardPreview` / `CardBasket` | Вызывается при клике на кнопку «Удалить из корзины» или «Мусорку» в списке корзины |
| `basket:open`    | `Page`           | Вызывается при клике на иконку корзины в шапке сайта для открытия модального окна корзины |
| `order:open`     | `Basket`         | Вызывается при клике на кнопку «Оформить» для перехода к первому шагу заказа |
| `order:submit`   | `FormOrder`      | Вызывается при отправке формы первого шага (клик на «Далее») для перехода к контактам |
| `contacts:submit`| `FormContacts`   | Вызывается при отправке финальной формы контактов для отправки заказа на сервер через API |
| `order:clear`    | `Success`        | Вызывается при клике на кнопку «За новыми покупками!» для полного сброса состояния приложения |
| `modal:open`     | `Modal`          | Вызывается при открытии любого модального окна для блокировки скролла страницы |
| `modal:close`    | `Modal`          | Вызывается при закрытии модального окна для разблокировки скролла страницы |

### Слой Презентера (Presenter)
Логика приложения, связывающая Модели данных (Model) и компоненты Представления (View), реализована в виде линейного кода управления внутри главного скрипта приложения `src/main.ts`. Файл выступает единой «диспетчерской вышкой», которая оркеструет работу всех независимых слоёв системы через брокер событий `EventEmitter` (паттерн Наблюдатель).

#### Архитектурный подход и роли в MVP:
* **Инверсия зависимостей:** Экземпляры моделей данных (`CatalogModel`, `BasketModel`, `BuyerModel`) и компонентов представления (`Page`, `Modal`, `Basket`, `FormOrder`, `FormContacts`, `Success`) инициализируются в корне файла `main.ts` и связываются друг с другом исключительно через интерфейсы и брокер событий. Компоненты ничего не знают о существовании друг друга.
* **Передача данных:** Презентер реагирует на события, генерируемые слоем View (клики по кнопкам, сабмиты форм, ввод текста), обновляет данные в соответствующих Моделях, а затем запрашивает свежее состояние моделей и передаёт его методам `.render()` компонентов View для перерисовки.

#### Основные сценарии логики, обрабатываемые в `main.ts`:
1. **Инициализация каталога:** При старте приложения Презентер вызывает метод `api.getProductList()`. Полученный массив товаров записывается в `CatalogModel`, которая генерирует событие `items:changed`. Презентер ловит его, создаёт экземпляры карточек `CardCatalog` для каждого товара и отрисовывает их в галерее главной страницы.
2. **Открытие превью товара:** При клике на карточку витрины Презентер переключает состояние `CatalogModel.setPreview(item)`, создаёт компонент `CardPreview`, проверяет наличие товара в корзине через `basketModel.isInBasket()` для настройки текста кнопки («Купить»/«Удалить»/«Недоступно») и выводит карточку в универсальное модальное окно.
3. **Управление корзиной:** Ловит события добавления (`basket:add`) и удаления (`basket:remove`) товаров. Вызывает соответствующие мутирующие методы в `BasketModel`. Модель генерирует событие `basket:changed`, по которому Презентер обновляет счётчик в шапке сайта. Если в момент изменения данных в модальном окне открыта именно корзина (проверяется по наличию DOM-элемента `.basket`), Презентер реактивно перерисовывает список строк `CardBasket` и актуализирует итоговую сумму «на лету», не затрагивая другие окна (например, окно успеха).
4. **Валидация и оформление заказа:** 
   * При клике «Оформить» принудительно сбрасывает данные модели покупателя методом `buyerModel.clearBuyerData()`, вычисляет стартовые ошибки пустых полей и рендерит первую форму `FormOrder` с изначально заблокированной кнопкой «Далее». 
   * При вводе данных (`input`) транслирует изменения в `buyerModel.setBuyerField()`. По событию `buyer:changed` Презентер запрашивает полный объект ошибок из модели, определяет имя активной формы (`order` или `contacts`) и изолированно передаёт в неё массив ошибок только для текущего шага оформления, предотвращая преждевременный вывод ошибок будущих экранов.
   * При сабмите первой формы переключает модалку на контакты `FormContacts` (действует аналогичная логика валидации).
5. **Отправка заказа на сервер:** При сабмите формы контактов Презентер собирает единый объект заказа `IOrder` (сливает данные покупателя, массив ID товаров и итоговую сумму). Отправляет данные на сервер методом `api.createOrder()`. При успешном ответе бэкенда Презентер очищает модели корзины и покупателя, обновляет счётчик на `0` и выводит окно успешной оплаты `Success` со списанной суммой.
